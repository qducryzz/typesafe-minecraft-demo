# Minecraft RCON 控制台参考手册

适用范围：本项目 main 工作树中的「开发者控制台 · RCON」，目标版本为 Minecraft Java Edition 1.21.4。命令根据当前服务器的 `help` 返回和项目实现整理；其他版本或插件服务器以自身 `help` 为准。

## 1. 打开与连接

1. 打开本地 dashboard，在 Minecraft backend 下方点击「开发者控制台 · RCON」。
2. 填写服务器主机、RCON 端口和 RCON 密码，点击「连接」。
3. 点击「在线玩家」验证服务器是否正常返回结果。
4. 要执行自定义命令，先暂停机器人任务，等待当前动作结束。

| 项目 | 常用端口 | 用途 |
| --- | --- | --- |
| Minecraft 游戏连接 | `25565` | Mineflayer 或游戏客户端加入世界 |
| RCON 连接 | `25575` | 管理员查询和执行服务器命令 |
| 本地 dashboard | `3010` | 浏览器操作页面 |

端口可以由服务器管理员修改。游戏连接和 RCON 连接互相独立：RCON 连上不代表机器人已经加入游戏，也不需要 TypeSafe API Key。

可在项目本地 `.env` 配置 RCON，或直接在面板中输入：

```dotenv
RCON_HOST=your-server.example
RCON_PORT=25575
RCON_PASSWORD=replace-with-your-password
```

上面的主机和密码是占位示例。修改 `.env` 后需要重启 dashboard。不要把实际密码写入文档或提交到 Git。面板输入的密码仅保留在后端会话内，提交后清空输入框；更换主机或端口需要对应服务器的密码。

## 2. 输入规则与结果含义

- 推荐不写开头的 `/`，例如输入 `list`。面板也会移除一个开头的 `/`。
- 每次执行一条命令，不支持多行批量输入。点击「执行命令」或按 `Ctrl+Enter` 提交。
- `<x>`、`<y>`、`<z>` 等尖括号表示必须替换的参数，不要原样输入。
- 帮助中的 `[参数]` 表示可选，`a|b` 表示二选一，不需要输入方括号或竖线。
- main 会按本机网卡 MAC 摘要自动生成 `TypeSafeBot` 加 5 位标识的名字，并显示在游戏连接区及 RCON 面板。以下 `TypeSafeBotA1B2C` 仅为示例，手动命令请替换为面板显示的真实名字；快捷查询会自动使用本机机器人名字。涉及实体查询、传送或给予物品时，目标玩家必须在线。
- RCON 是服务器控制台，没有你的游戏角色身份。涉及坐标或玩家时优先明确填写目标与绝对坐标，避免误用 `@s` 或相对坐标。
- 「已收到服务器响应」只代表收到文本。未知命令、目标不存在等错误也可能是正常响应，必须阅读输出内容。

## 3. 面板内置快捷查询

以下五个按钮为固定只读查询，机器人任务运行时也可使用。

| 按钮 | 实际命令 | 返回内容 |
| --- | --- | --- |
| 在线玩家 | `list` | 在线玩家数量和名称 |
| 机器人坐标 | `data get entity TypeSafeBotA1B2C Pos` | 机器人的 X、Y、Z 坐标 |
| 机器人背包 | `data get entity TypeSafeBotA1B2C Inventory` | 机器人背包数据 |
| 世界时间 | `time query daytime` | 当前昼夜周期中的游戏刻数 |
| 世界种子 | `seed` | 当前世界种子 |

**自定义输入框中的所有命令都要求任务暂停或停止，即使输入的是 `list` 等只读命令。** 运行中的只读查询请使用上述快捷按钮。

## 4. 常用查询与诊断

| 用途 | 命令 | 说明 |
| --- | --- | --- |
| 查看可用命令 | `help` | 返回当前服务器开放的命令入口 |
| 查看传送用法 | `help teleport` | 查看当前版本的参数格式 |
| 查看实体数据用法 | `help data` | 查看实体或方块数据相关语法 |
| 在线玩家及 UUID | `list uuids` | 排查玩家身份与在线状态 |
| 机器人生命值 | `data get entity TypeSafeBotA1B2C Health` | 读取生命值数据 |
| 服务器游戏刻状态 | `tick query` | 查询游戏刻运行状态 |
| 当前难度 | `difficulty` | 不带设置参数时查询难度 |
| 背包保留规则 | `gamerule keepInventory` | 不带新值时查询规则 |
| 白名单列表 | `whitelist list` | 查询已配置的白名单 |

常见现象：

- `list` 中没有 `TypeSafeBotA1B2C`：先在 dashboard 的 Minecraft backend 中连接游戏服务器。
- `data get entity ...` 提示找不到实体：检查机器人是否在线、名字是否正确，以及执行所在维度是否适用。
- 命令在当前版本语法不同：使用 `help <命令名>` 查询，不要反复提交修改世界的命令试错。

## 5. 调试时常用的修改命令

以下命令会改变玩家、世界或服务器状态，执行前先暂停机器人任务。本文仅提供参考，不会自动执行。

| 用途 | 命令 | 影响 |
| --- | --- | --- |
| 传送机器人 | `tp TypeSafeBotA1B2C <x> <y> <z>` | 将机器人移动到指定坐标；先确认落点和维度 |
| 切换生存模式 | `gamemode survival TypeSafeBotA1B2C` | Lumber Run 启动要求生存模式 |
| 切换创造模式 | `gamemode creative TypeSafeBotA1B2C` | 可用于人工调试，但不能直接启动正常 Lumber Run |
| 给予一把铁斧 | `give TypeSafeBotA1B2C minecraft:iron_axe 1` | 向机器人背包加入工具 |
| 设置白天 | `time set day` | 改变世界时间 |
| 设置晴天 | `weather clear` | 改变天气 |
| 调整为和平难度 | `difficulty peaceful` | 修改世界难度 |
| 死亡时保留背包 | `gamerule keepInventory true` | 修改全局游戏规则 |
| 恢复死亡掉落规则 | `gamerule keepInventory false` | 关闭背包保留 |
| 保存世界 | `save-all` | 请求服务器保存世界 |

例如，给予机器人一把铁斧：

```text
give TypeSafeBotA1B2C minecraft:iron_axe 1
```

执行后可点击「机器人背包」核对实际结果。

### 与 Lumber Run 验证的关系

Lumber Run 要求收集 **10 个新增原木**，然后回到任务记录的起点附近。手动给予原木、传送机器人或修改世界，会影响背包、位置和完成判断，不能当作模型自主完成任务的证据。

任务的起点和背包基线由开始任务时的状态决定。若人工调试改变了位置或背包，并希望重新设定起点与基线，应使用「Restart task」开始新任务；「Resume task」继续原任务，不重新设定基线。

## 6. 更多服务器命令

当前服务器的帮助还列出了以下命令族。先查看各自的 `help`，再填写参数。

| 类别 | 命令 | 用途 |
| --- | --- | --- |
| 方块与地形 | `setblock`、`fill`、`clone` | 修改单个方块、区域或复制区域 |
| 实体与效果 | `summon`、`effect`、`attribute` | 生成实体、施加效果或操作属性 |
| 执行上下文 | `execute` | 指定执行者、位置、维度或条件 |
| 物品与背包 | `give`、`item`、`clear` | 给予、修改或移除物品；`clear` 会删除目标背包中的物品 |
| 数据查询与修改 | `data` | 查询或修改允许操作的实体、方块和存储数据；玩家数据并非都可修改 |
| 世界规则 | `gamerule`、`time`、`weather`、`worldborder` | 修改规则、时间、天气或边界 |
| 性能诊断 | `debug`、`perf`、`jfr`、`tick` | 性能记录或游戏刻控制；具体可用操作以服务器为准 |
| 服务器管理 | `whitelist`、`ban`、`kick`、`op`、`deop` | 管理玩家访问和权限 |
| 保存与关闭 | `save-all`、`save-on`、`save-off`、`stop` | 保存策略和服务器关闭；`stop` 会停止服务器并断开连接 |

示例：

```text
help fill
```

这条命令只查询 `fill` 的用法。不要把帮助里展示的批量方块修改示例直接套用到现有世界。

## 7. 推荐调试流程

### 机器人不移动

1. 点击「在线玩家」，确认机器人在线。
2. 查看机器人坐标、背包；必要时暂停任务后查询 `Health`。
3. 查看 dashboard 的任务状态及实际工具结果，区分正在决策、无候选目标、寻路失败、等待和断线。
4. 检查 `runtime/trace-*.jsonl` 中的寻路状态和候选排除原因。
5. 如果需要人工传送，先确认安全落点，执行后再查询坐标。
6. 根据是否需要保留原起点与背包基线，选择 Resume 或 Restart。

### 验证 RCON 连通性

1. 连接成功后点击「在线玩家」。
2. 点击「世界时间」，确认同一连接能连续收到响应。
3. 暂停机器人后在自定义输入框执行 `help`。
4. 查看实际返回内容；连接成功只验证认证，命令响应才验证执行通道。

### 命令超时或断线

1. 不要立即重发修改世界的命令，上一条可能已经执行。
2. 重新连接，先使用只读查询核对实际状态。
3. 查阅命令历史和 trace 中相同 `rconCommandId` 的事件。
4. 确认前一次未生效后，再决定是否重新执行。

## 8. 当前面板限制

| 限制 | 当前实现 |
| --- | --- |
| 访问范围 | 仅本机、同源控制台请求 |
| 命令输入 | 每次一条，最多 1024 字节，不接受换行和空字符 |
| 并发 | 串行处理，上一条未结束时拒绝新命令 |
| 超时 | 连接、认证或命令响应约 8 秒 |
| 输出大小 | 单条命令最多 256 KiB |
| 命令历史 | 当前 dashboard 服务进程最近 50 条；重启后清空 |
| 自动重试 | 无；避免修改命令重复执行 |
| 关闭面板 | 只隐藏窗口；点击「断开」才关闭 RCON 会话 |
| 任务运行期间 | 内置快捷查询可用，自定义命令不可用 |
| 网络协议 | 原生 RCON 不加密，应使用可信网络或已有安全隧道 |

后端在收到命令首个完整响应包后，会发送一次只读 `list` 查询，用于确认分段响应已经结束。它不作为额外用户命令显示，不改变世界状态。

## 9. 日志与排查

每个工作树的本地日志相互独立：

- `runtime/trace-*.jsonl`：连接、命令开始、响应、错误和断开等诊断事件。
- `runtime/decisions-*.jsonl`：TypeSafe 任务决策记录。RCON 管理员操作不伪装成模型决策。

RCON 相关事件包括 `rcon.connect.start/end/error`、`rcon.command.start/end/error`、`rcon.disconnected` 和 `rcon.control-error`。命令事件通过 `rconCommandId` 关联，通用日志还包含会话、顺序号及时间戳。已配置的密码会在日志和返回内容中脱敏。

| 提示或现象 | 排查方向 |
| --- | --- |
| 请输入密码 | 面板未提供密码，且后端没有该端点的已配置密码 |
| Authentication failed | RCON 密码不匹配 |
| Connection refused / ECONNREFUSED | 地址、端口不正确，或服务没有监听 |
| Timeout / ETIMEDOUT | 网络不通、服务未响应或响应超时；不等于命令一定未执行 |
| Connection closed / ECONNRESET | 连接被对端关闭；重连后先核对实际状态 |
| 请先暂停机器人任务 | 当前自定义命令被任务互斥规则拦截 |
| 超过输出限制 | 改用范围更小的查询；原命令不会自动重试 |
| 未知命令或参数错误 | 执行 `help <命令名>`，按服务器返回的语法调整 |
